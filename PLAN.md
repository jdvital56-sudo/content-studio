## Этап 1. Стена по-настоящему

Один движок в начале (reel-factory для Kosta Method), потом стикмены и исторический.

1. **Договор движка** (готов 18.11, `docs/ENGINE-CONTRACT.md`). Завод отдаёт движку `job.json` и получает `final.mp4` + `meta.json` (длина, лицензии кадров, текст субтитров). Каждый движок подключается тонкой обёрткой, сами движки не переписываем.
2. **База** (SQLite, готова 18.11: `server/server.mjs`, запуск `node server/server.mjs`, адрес 127.0.0.1:8791, статусы и журнал сохраняются; осталось: копия на Диск) с карточкой ролика: канал, сценарий, хук, версия, статус, площадки, лицензии. Каждую ночь копия базы на Google Drive.
3. **Стена**: сетка с номерами, фильтры по статусу и каналу, переключатель каналов, размер S/M/L, клавиши 1–9, пробел, A, R.
4. **Автопроверка качества** (1080×1920, −14 LUFS, субтитры = речь до 3%, безопасные зоны, нет чёрных кадров и тишины). Не прошёл → кнопка «Опубликовать» серая.
5. **Упаковка**: подпись, хэштеги и обложка под каждую сеть; «пакет для ручной публикации» одной кнопкой.
6. Очередь **«Ждёт тебя»**, строка состояния ПК (диск, рендер, лимит Claude), понятные ошибки, корзина на 30 дней.
7. **Мастер паспорта канала** (идея владельца 17.11). Кнопка «Новый канал» → опрос по шагам: вид, кто в кадре, голос и текст, звук, язык, аккаунты, куда ведём, запреты. Каждый вопрос с советом и готовым вариантом, можно пропустить и вернуться. Итог сохраняется как файл `channels/<канал>.md`, тот же, что читают агенты. Пустые пункты видны на стене как «паспорт заполнен на 70%». Без готового паспорта канал не получает ночных сценариев. Каждая правка паспорта сохраняет прошлую версию.

Проверка: ролик из reel-factory появляется на стене, проходит проверку качества, владелец одобряет его и публикует руками.

## Этап 2. Ночные сценарии

Продюсер берёт тему → Сценарист пишет 10–20 сценариев по паспорту канала и скиллу канала → Критик ставит ГОТОВ или НЕ ГОТОВ с причиной → движки собирают ночью. Банк хуков копит хуки, которые позже сверяются с досмотрами.

Проверка: утром на стене N новых роликов, расход лимита известен.

## Этап 3. Нарезка говорящей головы

Сырой дубль → расшифровка → вырезаны паузы и дубли → субтитры в стиле канала → громкость −14 LUFS. Потом монтаж текстом (удалил слово, и кусок вырезался) и суфлёр для съёмки.

Проверка: таблица реальных дублей владельца, что вырезано и что должно остаться (правило проверки в обе стороны).

## Этап 4. Телефон и Telegram

Лента одобрения свайпами, «Поделиться» в приложение площадки, загрузка сырого видео, идея голосом, уведомления, сводка дня. Telegram-бот: одобрить, закинуть идею.

## Этап 5. Автоматика площадок

Автопубликация по одобренным API, сбор цифр, тепловая карта удержания, комментарий → директ для всех аккаунтов, новые площадки по одной.

## Экраны из исходного файла «Content OS» (сверка 18.11)

Макет `app/index.html` уже показывает: стену, фильтры, выбранный ролик, таймлайн сборки (видео, графика, голос, субтитры, музыка, звуки), шаги конвейера, полосу прогресса на карточках, кнопку «Тема → ролики», «Уникализатор ×3» (творческие варианты для A/B, без подмены метаданных).
Ещё не нарисовано, берём по порядку: мастер паспорта канала → канбан «Идея → … → Аналитика» → командная строка Cmd+K → календарь публикаций с предупреждением «на завтра мало контента» → радар трендов → аналитика с деньгами (UTM: просмотр → клик → заявка → продажа) → банк хуков → мобильная лента свайпов → журнал действий агентов → профиль голоса автора → мультиаккаунты и роли → шаблоны субтитров и интро в один клик → монтаж текстом (удалил слово, кусок вырезался).

## Добавки к мастеру паспорта (решено 17.11, Claude по поручению владельца)

Порядок: сверка с паспортом и учёба на отказах входят в этап 2 (там появляется Критик), папка бренда и копия паспорта входят в этап 1 вместе с мастером, черновик по ссылке идёт в этап 4. Опрос для клиента откладывается до первых платных клиентов.

- **Черновик паспорта по ссылке.** Вставил ссылку на аккаунт, агент читает открытый профиль и последние ролики и заполняет мастер заранее. Владелец только поправляет.
- **Сверка с паспортом.** Критик проверяет каждый сценарий и ролик по паспорту: язык, длина, запретные слова, цвета, CTA. Нарушение показано красным с пунктом паспорта.
- **Учёба на отказах.** Владелец отклоняет ролик и пишет причину. Если причина повторилась 3 раза, завод предлагает добавить правило в паспорт.
- **Папка бренда канала.** Логотипы, шрифты, музыка и фото с лицензиями, к ним ссылается паспорт. Движки берут файлы оттуда, а не ищут по дискам.
- **Копия паспорта.** Новый канал из похожего за минуту: скопировал, поменял отличия.
- **Опрос для клиента.** Позже, для платных клиентов: ссылка на тот же мастер, клиент сам заполняет паспорт своего бренда.
