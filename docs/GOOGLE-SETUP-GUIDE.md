# Подключение Google Диска и YouTube: пошаговая инструкция

Для тех, кто подключает завод к своему Google-аккаунту впервые. Время: 20–30 минут. Деньги не нужны, платёжную карту добавлять не надо.
Написана по тому, как это проходил владелец 17.11.2026, с ловушками, на которых он терял время.

**Три правила на весь путь**
1. Сверху слева всегда смотри на название проекта. Должно быть **content-studio**, а не чужой проект. Все ключи создаются только в нём.
2. Секретные значения (Client secret) не пересылай никому в чат и не пиши в документы. Их забирает скрипт из скачанного файла.
3. Перевод интерфейса бывает странным. «Давать возможность» = Enable (включить), «Создавать» = Create, «Заканчивать» = Finish. Если сомневаешься, ориентируйся на цвет кнопки: нужная синяя.

---

## Часть 1. Новый проект

1. Открой `console.cloud.google.com/projectcreate` (войди в свой Google).
2. **Название проекта:** `content-studio`. **Организация:** оставь «Нет организации». Платёжный аккаунт не выбирай.
3. Нажми **«Создавать»**. Через 10–20 секунд справа вверху появится уведомление.
4. Нажми на кнопку проекта слева вверху и выбери **content-studio**.
   *Ловушка:* в списке может не быть проекта без организации. Тогда нажми в окне на «jd-vital56-org ▾» (твоя организация) → «Нет организации». Или открывай страницы ссылками с `?project=<идентификатор>` (он виден в адресной строке после создания).

## Часть 2. Включить два API

1. Открой `console.cloud.google.com/apis/library/drive.googleapis.com` → синяя кнопка **«Давать возможность»**. Должно появиться «Статус: Включено».
2. Открой `console.cloud.google.com/apis/library/youtube.googleapis.com` → тоже **«Давать возможность»**.
   *Ловушка:* если сверху написано «Select a project», проект не выбран. Выбери content-studio и нажми кнопку снова.

## Часть 3. Экран входа (OAuth)

1. Открой `console.cloud.google.com/auth/overview` → **«Get started» / «Начать»**.
2. Четыре шага формы:
   - **Информация о приложении:** название `content-studio`, почта поддержки выбирается из списка (твоя) → «Следующий».
   - **Аудитория:** **Внешняя (External)** → «Следующий».
   - **Контактная информация:** твоя почта → «Следующий».
   - **Заканчивать:** галочка согласия → «Продолжить» → **«Создавать»**.
3. Внизу появится «Конфигурация OAuth создана».

## Часть 4. Права доступа

1. Слева **Data access** → **«Add or remove scopes»**.
2. Таблицу с галочками не трогай. Прокрути вниз до **«Manually add scopes»** и вставь две строки, каждую с новой:
   ```
   https://www.googleapis.com/auth/drive.file
   https://www.googleapis.com/auth/youtube.upload
   ```
3. **«Add to table»** → **«Update»** → внизу страницы **«Save»**. Внизу появится «Data access changes saved».
   `drive.file` даёт доступ только к файлам, которые создал сам завод. Остальной Диск он не видит.

## Часть 5. Тестовый пользователь

1. Слева **Audience** → блок **Test users** → **«+ Add users»** → своя почта → Save.
2. Должно появиться «1 user (1 test)». Тип пользователей остаётся External, статус Testing.

## Часть 6. Ключ (Client ID)

1. Слева **Clients** → **«+ Create client»**.
2. **Application type:** Desktop app. **Name:** впиши `content-studio-desktop`.
   *Ловушка:* в поле Name может стоять слово «Create» из перевода. Это не название, замени его.
   Галочку «Use this client for an AI-powered agent» не ставь.
3. **«Create»**. Появится окно с Client ID и Client secret.
4. **Не копируй значения вручную.** В этом окне нажми **«Download JSON»**: скачается файл `client_secret_....json` в папку «Загрузки».
   *Ловушка:* копирование длинных значений из окна даёт обрезанные или лишние символы, ключ получается неверный. Файл этого не допускает.
   Если окно уже закрыли: открой клиент из списка Clients → раздел Client secrets → **«+ Add secret»** → «Download JSON».
5. Файл никому не отправляй. Скрипт сам удалит его после подключения.

## Часть 7. Подключить Диск к заводу

Это делает Claude или человек, у которого установлен завод:

```
powershell -NoProfile -ExecutionPolicy Bypass -File C:\src\content-studio\tools\set-rclone-client.ps1
```

1. Скрипт найдёт скачанный файл (не старше 2 часов), откроется браузер.
2. Выбери свою почту. Если Google пишет «не проверил это приложение»: **«Дополнительно» → «Перейти на content-studio (небезопасно)» → «Разрешить»**. Это твоё приложение, пока оно в режиме тестирования, предупреждение нормальное.
3. В терминале: «ГОТОВО. Диск подключён через твой ключ.»

## Часть 8. Публикация приложения (чтобы вход не слетал каждые 7 дней)

В режиме Testing разрешение на вход живёт 7 дней, потом надо входить заново.

1. Слева **Audience** → **«Publish app»**. Если кнопка серая, сначала заполни **Branding**: название, почта поддержки, адрес главной страницы и адрес политики приватности, затем **Authorized domains** (домен этих страниц) → Save.
2. Нажми **«Publish app»** и подтверди.
   Для личного приложения с правом `drive.file` проверка Google не нужна. Для `youtube.upload` нужна отдельная проверка (аудит), см. API-SETUP.md.

## Если что-то пошло не так

| Что вижу | Что делать |
|---|---|
| «Select a project» сверху | Выбери content-studio и повтори шаг |
| Кнопка «Publish app» серая | Заполни Branding (Часть 8) |
| Скрипт: «Не нашёл файл client_secret» | Скачай JSON заново, запусти скрипт в течение 2 часов |
| Скрипт: «Нужен ключ типа Desktop app» | Ключ создан другого типа, создай новый по Части 6 |
| Google: «Доступ заблокирован» / access_denied | Твоя почта не в Test users (Часть 5) |
| Вход слетает через неделю | Приложение не опубликовано (Часть 8) |
| «redirect_uri_mismatch» | Тип ключа не Desktop app |
